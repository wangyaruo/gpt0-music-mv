# 长片实战：从 20 镜做到 130 镜

本文是一次完整长片（289 秒、129 镜、70 处交互、161 条合成音效）的复盘，
只收**跨项目可复用**的规律。文中数字都以 256×144 逻辑画布、scale=4 为前提；
换画布尺寸时比例可换算，但「先问视角」这类判断不变。

一句话结论：**长片的难点不在画得多，在画得不重复、不越界、不塌。**
下面九条分别对应这三件事。

---

## 一、「画面太少」通常不是镜头数的问题

接到「画面太少」的反馈时，第一反应往往是加镜头。但更常见的原因是：
**镜头落到了兜底分支上，或者只换了 palette。**

渲染器的 kind 分发是「查表 + 兜底」，两处都可能静默降级：

| 位置 | 分发方式 | 查询失败时画什么 |
|---|---|---|
| `pixel_world.scene_frame` | 先拦 composite / `RAIN_KINDS` / candy_road，再几个显式 `elif`（map / equipment / drive / battle / spotlight），最后 `else` | **最终 `else` 兜底**：`background(palette)` + 一个人站在 x=116（+partner 站在 +28），只有 `night`/`ending` 且有 partner 时才额外给一颗心 |
| `rain_scenes.render_rain_scene` | `SCENES.get(kind, street_scene)`，`SCENES` 目前只有 `rooftop` / `crossing` | **落到 `street_scene`**，它在内部再按 kind 加道具（站台、车厢、教室、书店…）|

所以写错一个 kind 名字**不会报错**，只会得到一张「渐变背景 + 一个人站着」的画，
和别的镜头长得一样。这是排查「画面重复」时要先看的一条。

还有一段**共享尾巴**：`scene_frame` 末尾会给除 `title`/`equipment`/`map`/`spotlight`/`ending`
之外的每个镜头，在左上角 y=7 处画三颗心 + 一枚金币。也就是说「每个镜头左上角都一样」
是结构性的，不是某个场景的设计选择；要做差异化，得从画面主体走，不能指望这层装饰。

一次实际事故：同一支片子里 5 个天台、3 个路口、3 个站台看着像「同一个空背景换了个颜色」，
镜头数并不少，是**画面熵**太低。原因就是这三类都只有 palette 差异，主体构图没变。

诊断方法（不用看片，读分镜就能查）：

1. 按 `kind` 聚一次类，列出每种的出现次数。
2. 对出现 ≥3 次的 kind，再按「除 palette 以外的参数」聚一次类。
   如果 5 个镜头的参数差异只有 `palette` 和 `label`，它们就是同一张画。
3. 重复率 = 「参数签名去重后的组数 / 镜头数」。低于 0.6 就说明在换色充数。
4. 顺手对一遍分镜里出现的每个 kind 是否真的在 `KIND_NAMES` / `SCENES` 里——
   拼错的名字会安静地拿到兜底画面。

处置顺序：先给高频 kind 加**可切换的构图参数**（机位、道具开关、时段），
再考虑新增场景类型。前者成本低得多，也不会让镜头表变长。

## 二、同一母题的重复：换底、换机位、换写法

有些母题注定要反复出现（副歌三次、同一个手势、同一扇窗）。删掉会伤叙事，
照原样重复会显得偷懒。三条改写路径，按代价从低到高：

| 手段 | 做法 | 代价 |
|---|---|---|
| 换底 | 同一前景，背景换成散景 / 平涂墙 / 冷压街景 / 雨 / 天空 | 一个 `bg` 参数 |
| 换机位 | 同一场景换 `view`（平视 / 仰拍 / 楼缝一线天 / 俯视） | 一个 `view` 分支 |
| 换写法 | 同一句话拆成两个动作（伸手没够到 / 举到一半落下） | 新姿势或新镜头 |

一条经验：**同一张画在全片出现不要超过 2 次；第 3 次必须换其中一项。**
如果母题本身只有有限的形态（例如内置手形只有 4 种），那就必须靠「换底」和「换机位」
把它们拉开——不要指望靠新手形解决重复，那是在给素材库加班。

## 三、扩镜的两种手段，以及切完必须重挂交互

1. **新增场景**：补叙事上一直缺位的事。判断标准是「片子进行到那里本来就该有，
   但前面 N 镜里没有的一格」——例如从天台下来没有过渡、全片没有一个「玩」的时刻。
2. **切长镜**：一个镜头撑 4 秒以上、画面一动不动时，从中间切一刀，补一格新画面。
   切点要落在**同一场景内部的视觉节拍**上，不是机械按秒数平分。

切长镜有一张必须记住的顺序表：

```
先把切点写进 SPLITS → 展开出新的 scene 边界 → 再把 dialogue/choice/events 挂上去
```

顺序反了会把交互挂到「已经不存在的 start」上，静默丢失。
所以切点和交互要**两张表分开**：`SPLITS`（时间点 + 新 kind）与 `PATCH`（按新 start 挂交互）。

切完还要过一遍**事件区间检查**：每个 `events[]` 的 `start/end` 必须完整落在
*同一个* scene 内。一刀切在事件中间，渲染器会在校验时报错；如果校验不严，
就会出现「进度条涨到一半被切走」的穿帮。

## 四、文字安全区：这是一组固定数字，不是感觉

256×144 画布下，官方叠加层的占位是确定的：

| 区域 | 坐标 | 谁占着 |
|---|---|---|
| 顶部 HUD 左 | y 0–30，x 0–70 | 队伍 / 场景标题 |
| 顶部 HUD 中 | y 0–30，x 97–197 | 心跳或量表条 |
| 对白框 | y 26–54，x 6–250 | `dialogue` 文字框与头像 |
| 卡拉 OK 字幕 | y 118–144 | 双行从 y 122 起，单行从 y 130 起 |

推论：**自定义面板里任何「必须读到的文字」都不要落进 y 26–54 和 y 118 以下。**
可用的中段是 y 55–117，实际排版建议压到 y 58–112，留一点边。

只有一种例外：镜头整屏自绘、且**不画对白和字幕**（把该镜头排除在默认叠加层之外），
这时才能用到 y 94–130。这种做法要在渲染器里有一份显式白名单，
不要靠「反正这个镜头没对白」的巧合。

同一个镜头里，`dialogue`/`choice` 与 `checkpoint`/`stage_clear` 都会抢顶部中心区，
必须拆成两个场景。

## 五、写自定义场景之前，先答三个问题

画崩的场景，十次有八次是没答这三个问题就动手：

1. **这个画面是从哪个视角看的？** 俯视 / 平视 / 仰拍 / 贴地低角度。
   决定了「什么东西该出画」「什么该被压扁」。
2. **主光源在哪，受光的是哪一面？** 掀开的盖子露出的是内面；橱窗里的灯照的是玻璃内侧。
   受光面画反，物体就变成一个说不清的几何体。
3. **这个物体和画框的关系是什么？** 桌面上摆的、贴在地上的、悬在空中的。
   凡是「贴在地/水面上」的东西，靠近观者的一侧必须**出画**。

四条具体事故，可以直接当检查表用：

- **俯视的水面不能画成平面图形。** 水洼画成一个完整椭圆、下沿收在画面里，
  会读成一块浮在地上的镜子；正确做法是让椭圆下沿推到画外，只露远岸一条弧。
- **倒影不能把街景直接上下翻转。** 翻转后的天空与楼亮度接近，出来是一团灰。
  要手画倒影剪影（矩形 + 固定窗口点），只让窗灯带暖色。
- **霓虹灯管要连笔。** 沿参数方程取 64 个顶点逐点画，顶点间距约 3.6 px，
  1 px 的点之间必然露缝，看上去是虚线；改成相邻顶点 `line(width=2)` 才成立体的玻璃管。
- **水面上的「碎光」要画成暗线。** 亮线（比水色浅）画出来像横梯；
  而且必须画在被水面 mask 裁掉的图层里，否则会横穿干地，把路面切成横条。

## 六、Pillow 的五个工程坑

1. **RGBA 画布上 `draw.xxx(fill=(r,g,b,a))` 是覆盖，不是混合。**
   转 RGB 时 alpha 被直接丢掉，`a=5` 的浅色会变成实心亮块（一次事故：砖墙整面变白）。
   要半透明，必须画在独立 layer 上再 `alpha_composite`。
2. **`mask.resize()` 不吃 float。** `(w*scale, h*scale)` 必须 `int()` 且 `max(1, ...)`，
   否则 `TypeError: 'float' object cannot be interpreted as an integer`。
3. **文字抗锯齿会破坏像素网格。** 想在像素画上放字，在逻辑画布上写字后
   把 mask 二值化（阈值 ~110）再贴实色，放大后边缘才落在格子边界上。
4. **缩放只能是 `NEAREST` + 整数倍。** 非整数倍会让像素颗粒变成不规则的软边，
   整片气质立刻从「像素」变成「低清」。
5. **发光类是 alpha 叠加，圈数要克制。** 七圈 alpha=6 的圆叠起来 ≈ 15% 累积，
   会变成一块灰盘；三圈 alpha=3 才是光晕。

## 七、音效：按镜头类型铺，不按时间轴铺

音效最容易做砸的方式是「每切一刀给一声」。实际量级参考：

- **翻页声要有闸门**：初版「kind 一变就响」，129 个镜头几乎每一刀都是类型变化，
  变成每 2.5 秒一声 whoosh，整段糊成翻书声。改成「kind 变化 **且** 距上次 ≥ 4.2 秒」，
  只剩 50 声；章节卡片（片头 / 地图 / 聚光灯 / 片尾）不受闸门限制，过场该有的分量还在。
- **每个高频 kind 配一种专属音色**：电梯 → 金属铃，抓娃娃机 → 电机 + 咬合，
  音游 → 连击 tick，翻牌时刻表 → 塑料片翻面，霓虹 → 电流嗡声，八音盒 → 齿梳四音。
  听起来「有物」的关键是音色和画面里的**材质**对应，不是音高好听。
- **铺轨挂在字段上，不挂在秒数上**：从 `dialogue` / `choice` / `events` 反推时间点，
  改分镜后重跑脚本，音效自动跟着走。硬编码秒数的音效轨在第二次改片时就废了。
- **响度按测量调，不按耳朵调**：判据取「音效峰值 vs 同窗原曲 RMS」，
  中位数落在 −12 ~ −13 dB 可辨。原曲已贴顶时，先对原曲做软限幅（tanh）吃掉越界样本，
  再压音效峰值，别靠整体调小音量。

## 八、封面与物料：和成片同一套网格

封面不是「截一帧加拉字」。可用的做法是**同源出图**：

- 新开一份逻辑画布（横 480×270、竖 270×480），沿用同一套配色与画法，最后 ×4 最近邻。
  这样封面和成片的像素颗粒是同一个尺寸，摆在一起不会打架。
- 文字同样画在逻辑画布上并二值化。直接贴矢量字会「太干净」，和底下的像素画不是一套语言。
- 三项具体参数：**星按「面积/42」铺是下雪**，一屏 700–900 颗才像夜空；
  月亮光晕别叠七圈；**左对齐的字不能用居中算法摆**，否则首字会顶出画框。
- 小道具要按尺寸取舍。楼只有 60–90 px 高时，屋顶水塔会读成一块悬空的黑，
  删掉比留着干净；一根天线反而成立。

交付时横竖各出一版（16:9 与 9:16），不要只给横版让用户自己裁。

## 九、验收：抽帧不是抽查一帧

改完全片后至少抽 9–10 帧拼一张 contact sheet 一起看，覆盖：

```
开场 1 帧 / 每个新增镜头 1 帧 / 每个改动过的镜头 1 帧 / 片尾卡 1 帧 / 结算屏 1 帧
```

拼图一起看，比逐张看有用得多——重复和不统一是在并排时暴露的。单帧预览用
`--still <秒>`，先确认关键镜头，再渲全片（129 镜约 1 分钟，不必省这一步）。

另外两条容易被忘的收尾：

- **片子里的元信息越少越好。** 「像素同人 MV · 脚本渲染」这类制作说明属于简介，
  不属于画面。片尾只留歌名与歌手名，是更稳的默认。
- **画面里的数字要由脚本现算。** 结算屏上的「N 镜 / M 处交互 / 时长」如果手写，
  改完分镜必然忘改。让它从分镜对象里算，改片就等于改数字。
