# 歌曲定位与选景

每首歌先做一次独立定位，再挑选和创作场景。参考片提供像素 RPG 的叙事手法与镜头语言，不自动继承天气、城市、雨伞、情侣关系、故事或色板。用户明确要求的题材、视觉风格、禁用元素和故事设定优先；在不冲突的部分再根据歌词与音乐做创作。

## 1. 建立证据和方向

- 通读歌词：识别叙事视角、人物关系、地点、明确发生的事件、反复出现的意象与情绪变化。区分字面场景与比喻，例如“心里下雨”不必直接画下雨；仅出现一次的意象不必贯穿全片。不要把没有证据的恋爱、离别或悲伤当成主题。
- 听完整首歌：记录听到的速度感、配器、疏密和情绪转折；按实际时长标注引子、主歌、副歌、间奏和尾声，难以确定时标记待确认。音频工具不可用或无法听到时，不要声称听过、确认曲风或细分曲式。
- 可运行 `python3 scripts/analyze_song.py /path/song.mp3 --out output/song-analysis.json` 提取时长、分段 RMS、可选 BPM 候选。安装 NumPy 时才有自动 BPM 候选；半拍/倍拍可能混淆。RMS 是信号强度，不是情绪、响度标准或主副歌判别器；候选必须听音核对。
- 先写简短的 `creative-brief.md` 或同类文件：**用户要求、歌词证据、听音/信号观察、叙事主题、情绪变化、主要地点、天气与时段、色板、角色关系、重要母题、待确认项**。对每项方向注明依据是用户指定、歌词、听音还是创作假设；没有证据就标为假设。不要照抄原歌词到公开视频项目，除非用户明确授权使用。

## 2. 将方向映射为场景

逐句或逐乐段记录：`歌词/歌曲段落 → 含义及变化 → 游戏动作与后果 → 地点/天气/时段/色调 → 选用的场景或新资产`。地点、天气、时段和叙事应分开决策：晴天、夜晚、室内、雪景、梦境或抽象世界都可以服务不同歌曲；没有依据时选与整体方向协调的中性环境，不机械套用雨天。

例如：

- 明确写到旅行、阳光与启程，音乐明快：可以设计晴天道路、地图与拾取行动；不要因为另一个示例有公交站就加入雨伞。
- 明确写到雨中等待且用户也希望保留雨意象：可以在对应乐段使用雨夜站台，后续是否转晴由歌词、听感和叙事决定，不强制整片下雨。
- 歌词表达思念但没有具体天气：可以用窗边、旧物、远近距离变化等表达，天气保持中性或由用户要求确定；思念不自动等于雨天。

这些是说明方法的虚构例子，不是关键词分类器。请综合整首歌曲与用户要求决定；即使歌词出现“雨”，也可按语境将它处理为比喻。

## 3. 选素材、检查偏差

- 先判断既有场景能否表达定位。`rain_city` 默认有雨，`bus_stop` 默认无雨，但两者现有底图都是夜间城市；雨夜示例仅在内容适配时采用。`weather: clear` 不能把该夜景底图变成白天。
- 不适合时用 `composite` 图层、外部背景和精灵构建新地点；必要时制作新的原创素材。仅因现有素材有限就强行改变主题，应明确告知用户限制；没有所需工具时交付可编辑分镜或说明需补充的资产，不虚称已实现。
- 对照 `creative-brief.md` 检查主色、天气、地点、关系与重要事件是否有来源。观察有没有把雨天、伤感或恋爱当作默认值；发现偏差就修改分镜和素材。反复副歌可以沿用母题，但应随歌曲推进发生变化。
- 显式写入天气等关键选择，不依赖样例隐含的默认值。保留用户指定的风格、参考片镜头语言和歌词的真实含义；最终交付时简述选择依据和尚未确认的项目。
